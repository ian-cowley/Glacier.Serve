# OpenAI HTTP API Reference: Chat Formatting, Stop Tokens, and SSE Delimiter Suppression

**Document Type:** Diátaxis Reference  
**Subsystem:** `Glacier.Serve`  
**Related Components:** `OpenAiEndpoints.cs`, `ContinuousBatchEngine.cs`, `InferenceRequest.cs`, `ServeJsonContext.cs`  
**Status:** Production Normative Reference  

---

## 1. Overview

`Glacier.Serve` provides production-grade, drop-in compatibility with the OpenAI HTTP API specification. All endpoints support both standard JSON batch responses and low-latency Server-Sent Events (SSE) token streaming.

This document serves as the formal API reference for endpoints `/v1/chat/completions`, `/v1/completions`, and `/v1/models`, detailing schema contracts, sampling parameters, multi-turn chat templates, stop token arrays, and SSE delimiter suppression mechanics.

## 2. API Endpoints

### 2.1 `POST /v1/chat/completions`

Generates model completions for a multi-turn conversational message history.

#### Request Headers:
- `Content-Type: application/json`
- `Accept: text/event-stream` (when `stream: true` is requested)

#### JSON Request Schema (`InferenceRequest`):
```json
{
  "model": "glacier-enterprise-7b",
  "messages": [
    {
      "role": "system",
      "content": "You are an expert systems programming assistant."
    },
    {
      "role": "user",
      "content": "Explain how PagedAttention operates in pure C#."
    }
  ],
  "temperature": 0.0,
  "top_p": 1.0,
  "top_k": 40,
  "max_tokens": 2048,
  "stream": true,
  "stop": ["<|im_end|>", "<｜end of sentence｜>", "[DONE]"]
}
```

#### Request Parameter Specification:
| Field | Type | Required | Default | Description |
| :--- | :---: | :---: | :---: | :--- |
| `model` | `string` | Optional | Default model | Identifier of the model to execute. If omitted or null, defaults to the loaded model. |
| `messages` | `array` | Required | — | List of chat message objects with `role` and `content`. |
| `temperature` | `float` | Optional | `0.7` | Sampling temperature. `0.0` triggers deterministic greedy argmax sampling. |
| `top_p` | `float` | Optional | `0.9` | Nucleus sampling threshold (cumulative probability mass cutoff). |
| `top_k` | `int` | Optional | `40` | Limits sampling pool to top-$K$ most likely tokens. |
| `max_tokens` | `int` | Optional | `2048` | Maximum number of new tokens to generate before stopping. |
| `stream` | `bool` | Optional | `false` | If `true`, returns chunks via Server-Sent Events (`text/event-stream`). |
| `stop` | `string[]` or `string` | Optional | `null` | Custom client stop sequences. Generation halts immediately if encountered. |

### 2.2 Non-Streaming Response Contract

When `stream: false`, the server responds with a complete JSON completion payload once generation terminates.

#### Response Headers:
- `Content-Type: application/json`
- `Status: 200 OK`

#### JSON Response Schema:
```json
{
  "id": "chatcmpl-a8f3b4c1-d2e5-4f6a-8b9c-1d2e3f4a5b6c",
  "object": "chat.completion",
  "created": 1729699200,
  "model": "glacier-enterprise-7b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "PagedAttention partitions the physical Key-Value cache into fixed-size contiguous blocks..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 42,
    "completion_tokens": 312,
    "total_tokens": 354
  }
}
```

#### Finish Reasons:
- `"stop"`: Model naturally emitted an EOS / stop token or hit a client stop sequence.
- `"length"`: Generation reached `max_tokens` without hitting an EOS token.
- `"pool_oom"`: Physical KV block pool was completely exhausted under extreme concurrency.

### 2.3 Streaming Response Contract (SSE)

When `stream: true`, the server initiates an HTTP chunked stream with `Content-Type: text/event-stream`. Tokens are emitted to the client in real-time as they are decoded from the GPU.

#### Stream Lifecycle:
1. **Initial Header Dispatch:** `GlacierServeApp` sends standard SSE headers:
   ```http
   HTTP/1.1 200 OK
   Content-Type: text/event-stream
   Cache-Control: no-cache
   Connection: close
   ```
2. **Token Delta Chunks:** As each token is generated by `ContinuousBatchEngine`, an SSE chunk is serialized directly to the socket body writer via `WriteSseChunk`:
   ```
   data: {"id":"chatcmpl-9b8a...","object":"chat.completion.chunk","created":1729699200,"model":"glacier-enterprise-7b","choices":[{"index":0,"delta":{"content":"Paged"},"finish_reason":null}]}

   data: {"id":"chatcmpl-9b8a...","object":"chat.completion.chunk","created":1729699200,"model":"glacier-enterprise-7b","choices":[{"index":0,"delta":{"content":"Attention"},"finish_reason":null}]}

   ```
3. **Terminal Chunk:** When generation finishes, a final chunk carries the `finish_reason`:
   ```
   data: {"id":"chatcmpl-9b8a...","object":"chat.completion.chunk","created":1729699200,"model":"glacier-enterprise-7b","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

   ```
4. **Stream Termination Signal:** The stream concludes with the standard OpenAI sentinel:
   ```
   data: [DONE]

   ```

## 3. Streaming SSE Delimiter Suppression

A critical failure mode in naive LLM servers is leaking raw delimiter strings (e.g., `<|im_end|>`, `<｜end of sentence｜>`, `</s>`) into the final client chunks.

### 3.1 Mechanics of Delimiter Suppression

In `Glacier.Serve`:

```mermaid
sequenceDiagram
    participant Engine as ContinuousBatchEngine
    participant Sampler as Sampler
    participant Runner as PagedTransformerRunner
    participant Channel as Channel<string>
    participant SseWriter as OpenAiEndpoints (WriteSseChunk)

    Engine->>Runner: StepBatch(Active Sequences)
    Runner-->>Engine: Logits Batch
    Engine->>Sampler: Sample next token ID
    Sampler-->>Engine: Token ID (e.g. 151645)

    rect rgb(255, 235, 235)
        Note over Engine: IsEosToken(token) Check
        alt Token is Stop Token (151645 / <|im_end|>)
            Note over Engine: Suppress Decode & Emission!
            Note over Engine: seq.IsFinished = true; seq.FinishReason = "stop"
            Engine->>Channel: Writer.TryComplete() (NO string emitted)
            Note over Engine: seq.BlockTable.ReleaseAll()
        else Token is Valid Content (e.g. " world")
            Engine->>Channel: Writer.TryWrite(" world")
            Channel->>SseWriter: Read token string
            SseWriter->>Client: Send SSE Data Chunk
        end
    end
```

### 3.2 Invariants Enforced:
1. **Pre-Emission Verification:** The method `IsEosToken(sampledToken)` is evaluated *before* the token string is decoded or placed onto the sequence's output channel.
2. **Channel Closure Without Payload:** If `IsEosToken` returns true, `seq.TokenChannel.Writer.TryComplete()` is called immediately. Zero bytes of delimiter text are written to the channel.
3. **Clean SSE Stream:** The client receives all semantic text tokens up to the end of the sentence, followed directly by the terminal `finish_reason: "stop"` chunk and `data: [DONE]`.

## 4. `POST /v1/completions` (Raw Text Completion)

Supports legacy single-prompt text completion without conversation wrapping.

#### Request Schema:
```json
{
  "model": "glacier-enterprise-7b",
  "prompt": "The capital of France is",
  "temperature": 0.0,
  "max_tokens": 10
}
```

#### Behavior:
When `messages` is null or empty, `req.Prompt` is tokenized directly as raw text without prepending or appending chat template headers.

## 5. `GET /v1/models`

Retrieves active models available for inference.

#### Response Schema:
```json
{
  "object": "list",
  "data": [
    {
      "id": "glacier-enterprise-7b",
      "object": "model",
      "created": 1710000000,
      "owned_by": "glacier"
    }
  ]
}
```

## 6. End-to-End Curl Examples

### Streaming Chat Completion:
```bash
curl -X POST http://localhost:5000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glacier-enterprise-7b",
    "messages": [
      {"role": "user", "content": "What is the speed of light in m/s?"}
    ],
    "temperature": 0.0,
    "stream": true
  }'
```

### Non-Streaming Chat Completion:
```bash
curl -X POST http://localhost:5000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glacier-enterprise-7b",
    "messages": [
      {"role": "user", "content": "Hello!"}
    ],
    "temperature": 0.7,
    "stream": false
  }'
```
